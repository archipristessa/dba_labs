**Дата проверки:** 2026-11-05
**СУБД:** PostgreSQL 18.6 (Windows x86_64), база `eshop`

### Аутентификация и авторизация

- [x] Метод аутентификации в `pg_hba.conf`: **scram-sha-256** — для `local` и `host` (127.0.0.1/32, ::1/128)
      записей нет ни с `trust`, ни с `md5`. Проверено: `SELECT * FROM pg_hba_file_rules WHERE auth_method <> 'scram-sha-256';` — пусто.
- [x] Нет пользователей с пустым паролем: все 8 ролей (`postgres`, `app_backend`, `analyst_ivanova`,
      `analyst_petrov`, `repl_user` и групповые `eshop_app`, `eshop_readonly`, `eshop_report`)
      имеют SCRAM-хэш в `pg_authid`; групповые роли созданы с `NOLOGIN`.
- [x] Роли разделены: **readonly** (`eshop_readonly`) / **app** (`eshop_app`, `app_backend`) /
      **report** (`eshop_report`) / **dba** (`postgres`) / **replication** (`repl_user`).
      `app_backend` — член `eshop_app`; `analyst_ivanova` — член `eshop_readonly`; `analyst_petrov` — `eshop_report`.
- [x] RLS включён для чувствительных таблиц: `customers` — политика `customers_by_region`
      (`FOR SELECT TO eshop_readonly USING (region = current_setting('app.current_region', true))`).
      Проверено: аналитик с `SET app.current_region='MSK'` видит **1 007** строк из 20 000;
      без установки параметра — **0** строк.

### Сеть и транспорт

- [x] SSL включён: `ssl = on`, `ssl_cert_file = 'server.crt'`, `ssl_key_file = 'server.key'`
      (самоподписанный `CN=localhost`, срок действия 365 дней).
      Проверено: `SELECT ssl, version, cipher FROM pg_stat_ssl ...` → `t | TLSv1.3 | TLS_AES_256_GCM_SHA384`.
- [x] Для приложения: `hostssl` в `pg_hba.conf`:
      `hostssl eshop app_backend 127.0.0.1/32 scram-sha-256` + `hostnossl ... reject`
      (правила стоят выше общих `host`-правил). Проверено: `sslmode=require` подключается,
      `sslmode=disable` получает `FATAL: pg_hba.conf rejects connection ... no encryption`.
- [ ] Порт 5432 не открыт наружу (только через VPN / jump-host). **Не выполнено:** на учебном стенде
      PostgreSQL слушает `localhost`; проверка внешнего периметра выходит за рамки лабораторной.
      Для production: `listen_addresses = 'localhost'` либо firewall-правило «только из подсети приложений».

### Аудит

- [ ] `pgaudit` установлен и настроен: `pgaudit.log = 'write,ddl,role'`. **Заблокировано:**
      расширения `pgaudit` нет ни в поставке PostgreSQL 18 для Windows (`pgaudit.dll`
      и `pgaudit.control` отсутствуют), ни в каталоге EDB Stack Builder 4.2.2 для PG 18
      (проверено вручную), ни в виде бинарной сборки на GitHub. Сборка из исходников невозможна:
      в системе нет MSVC.
      **Временная замена** (проверена): `log_statement = 'ddl'`, `log_min_duration_statement = 500`,
      `log_connections = on` — операции записи и DDL попадают в журнал, но без метки `AUDIT:`
      и без разделения по объектам.
- [x] Логи аудита хранятся отдельно и не перезаписываются: `logging_collector = on`,
      файлы `postgresql-%Y-%m-%d.log` в `data/log`, `log_rotation_age = 1d`,
      ротация по дням без удаления предыдущих файлов.
- [ ] Период хранения логов: 1 год (требование 152-ФЗ). **Запланировано**, технически не настроено:
      нужна внешняя сборка логов (syslog/Filebeat) и политика хранения — на стенде не реализуется.

### Шифрование данных

- [x] Поля с персональными данными (`phone`) зашифрованы: расширение `pgcrypto 1.4`,
      колонка `customers.phone_encrypted BYTEA`, алгоритм — `pgp_sym_encrypt(phone, key)` (AES + MDC).
      Зашифровано **20 000** строк; расшифровка проверена: 20 000 / 20 000 совпали с исходными номерами;
      неверный ключ → `ERROR: Wrong key or corrupt data`. Открытый `phone` замаскирован (`'***'`).
- [ ] Ключ шифрования НЕ хранится в БД. **Частично:** в учебной работе ключ передаётся в SQL-тексте
      (`'secret_key_2024'`), что для production недопустимо. Целевая схема: ключ в Vault/HSM,
      приложение передаёт его при каждом запросе.
- [ ] Резервные копии зашифрованы. **Не выполнено:** дампы в `C:\backup\eshop` лежат в открытом виде.
      Для production: `gpg -r dba@eshop -e` или `openssl enc -aes-256-cbc` после `pg_dump`.

### 152-ФЗ (персональные данные)

- [x] Локализация: PostgreSQL установлен на сервере в РФ (учебный стенд, `DESKTOP-DR4C95N`),
      база не реплицируется за пределы РФ.
- [x] Категория ПДн: **общие** (ФИО, email, телефон) — **3-й уровень защищённости**
      (УЗ-3 по ПП РФ № 1119: специальные категории не обрабатываются, биометрия отсутствует,
      субъектов менее 100 000, угрозы 2-го типа актуальны не для всех ИСПДн).
- [ ] Документ «Согласие на обработку ПДн» подписан пользователями — организационная мера,
      вне рамок стенда; требуется до промышленной эксплуатации.
- [ ] Назначен ответственный за обработку ПДн — организационная мера; для учебного стенда
      ответственный не назначен.

### Организационные меры для 3-го уровня защищённости (УЗ-3)

1. Приказ о назначении ответственного за обработку ПДн и лица, замещающего его.
2. Перечень ПДн и мест их хранения (модель угроз, акт определения уровня защищённости).
3. Политика обработки ПДн и правила разграничения доступа (роли `eshop_app` / `eshop_readonly` /
   `eshop_report` / `postgres` — реализуют принцип минимальных привилегий).
4. Журналирование доступа к ПДн и контроль сроков хранения (после установки `pgaudit`).
5. Согласия субъектов ПДн на обработку; порядок отзыва согласия и удаления данных.
6. Регламент резервного копирования с шифрованием копий (`backup/backup_policy.md`).
